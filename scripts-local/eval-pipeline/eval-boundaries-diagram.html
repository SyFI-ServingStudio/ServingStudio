Eval pipeline · system boundaries · technical view

Where each piece runs

The eval harness lives outside VibeSim (untracked scripts-local/, never visible to the agent). VibeSim contributes the backend, the analyzer, and the sandboxed agent runtime. They meet at one shared, bind-mounted workspace repo.

Trust boundary

What the agent can reach

The sandbox sees exactly three things: the bind-mounted repo at /workspace, the analyzer's evidence API over MCP, and its own toolchain. Launched with CODEX_DOCKER_GPUS="" — no GPU device exists inside. It never sees the issue spec, the ground truth, the gate code, or scripts-local/.

Inside vs outside

VibeSim's role

VibeSim supplies the runtime: the backend (:8766) manages conversations and docker-execs the agent; the analyzer (:8788) serves cost-tree evidence. The eval harness — trial driver, gate logic, judge client, GT spec — is separate host code that only talks to VibeSim over REST.

Shared state

One repo, two views

Agent (in-container) and gate (host) operate on the same working tree. The agent commits on a branch; the gate re-simulates that tree from the pinned before.json + warm profile.db, cache-only. run_trial.py git-resets it between trials.
