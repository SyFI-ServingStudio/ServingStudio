Eval pipeline · vLLM #28103 · k-trial harness

Can the agent rediscover the PR fix?

One trial of the optimization eval: a fresh gpt-5.6-luna agent gets only the "before" state and a goal — no spoilers — then a deterministic sim gate and an LLM judge score what it did. Repeated k times, sequentially, on one shared workspace.

Why it can't be cheated

Objective gate

The gate ignores the agent's own numbers: it re-simulates the agent's edited repo from a pinned before.json, so swapping configs to the "after" arch still selects the unfixed model and fails. PASS iff the redundant *_input_copy leaves vanish, R0/R5 land within tolerance of the real PR's "after", and necessary work (R6) is unchanged.

Why it's safe

Zero-GPU by construction

Agent containers launch with CODEX_DOCKER_GPUS="" — no device is mounted, so any profiling attempt fails harmlessly. The gate's re-sim reads the warm profile.db cache; a cache miss errors instead of grabbing a GPU.

How it's scored

k trials, two rates

Each trial is a fresh agent conversation on a reset repo. summary.json reports gate_pass_rate (did the fix work) and judge_match_rate (did the agent name the true root cause). A trial counts as correct only if the objective gate passes.
